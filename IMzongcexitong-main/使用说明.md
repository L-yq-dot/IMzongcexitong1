# 学生素质综合测评数据库

适用 MySQL 8.4。建库脚本按北京大学信息管理系 2024 级及以前、2025 级及以后两份实施细则实现：`S = A 基本素质（20）+ B1 学业成绩（80）+ B2 学术科研（加分）+ C 实践能力（加分）`。24 级及以前 B1 = 课程平均绩点 × 20；25 级及以后 B1 = 课程加权平均分 × 0.8。结果只有优秀/合格/不合格，优秀不超过年级测评范围的 20%，A 不合格或学业不合格直接不合格。

共 24 张基表：20 张业务表和 4 张审计/日志表，全部满足 1NF、2NF 与 3NF；没有 JSON 嵌套列，材料 SHA-256 查询时计算，排名按年级独立成表。

## 导入

在 MySQL Workbench 中用具有建库、创建过程、角色授权和 `SYSTEM_VARIABLES_ADMIN` 权限的账号（如 root）运行 `01_创建数据库.sql`。需要虚构演示数据再运行 `02_演示数据.sql`；接入网页再运行 `03_网页接口.sql`。

也可以在 CMD 中依次执行：

```bat
mysql --default-character-set=utf8mb4 -u root -p < "01_创建数据库.sql"
mysql --default-character-set=utf8mb4 -u root -p < "02_演示数据.sql"
mysql --default-character-set=utf8mb4 -u root -p < "03_网页接口.sql"
```

目标库为 `student_assessment`。演示脚本只在刚建好的空库运行；`demo.py` 会自动创建全部演示账号并授予默认角色。

## 真实口径

- **A 基本素质**：满分 20。学生互评（15）+ 班主任/辅导员评价（10）合计 25 后乘 0.8。上一学年受学校纪律处分则 A 不合格。
- **B1 学业成绩**：满分 80。24 级及以前用课程平均绩点 × 20；25 级及以后用课程成绩加权平均分 × 0.8；合格制/等级制课程不计。上一学年两门必修课不及格则学业不合格。
- **B2 学术科研**：基础 0。论文、著作、课题、竞赛、知识产权按细则分档；合作成果按第一/通讯作者、责任者顺序、团队人数、作者顺序公式折算。
- **C 实践能力**：基础 0。社会工作、志愿服务、实践活动按细则分档；社会工作多项取最高一项，志愿服务按年级排名前 30%，竞赛同一项目取最高且每年最多 2 项。
- **结果**：优秀/合格/不合格。A 不合格或学业不合格直接不合格；其余按年级总分排序，优秀人数不超过 `FLOOR(年级人数 × excellent_ratio)`，默认 20%。

## 业务操作

管理员先录入班级、学生（含入学年）、审核人员、规则、加分项目和学年。规则按 `cohort` 区分 `le2024` 与 `ge2025`；同一学年可以同时套用两套规则。项目只表示 B2/C 加分项，A/B1 不是学生申报项目。

| 使用者 | 操作 |
| --- | --- |
| 班级工作组/管理员 | 用 `set_base_assessment(学年, 学号, A, B1原始值, A不合格, 学业不合格)` 录入基础分；不存在档案时自动建档。网页端「基础分录入」由班级初审员使用。 |
| 学生 | 用 `web_projects(学年)` 查本人规则下的 B2/C 项目；用 `save_form(学年,说明)` 建档；用 `save_item(学年,条目编号,项目编号,细节,申报分,发生日期)` 保存加分条目；用 `add_evidence` 上传证明；用 `submit_form(学年)` 提交。没有加分项也可以提交空表，A/B1 仍参与测评。 |
| 学生修改 | 截止前用 `reopen_form(学年)` 撤回为草稿，可修改条目、移除材料，重提后从初审重走。 |
| 学生自查 | `my_form_status`、`my_evidence`、`my_submission_history`、`my_result`、`my_progress`、`public_notice`。 |
| 审核人员 | 用 `review_queue(学年,筛选值)` 看范围；`read_review_item` 看详情、附件和历史；`review_item(条目编号,结论,意见,核定分)` 处理。只有终审通过填核定分；核定分不超过申报分和单项上限；同表单同项目累计不超过项目总上限（若设置）。 |
| 审核辅助 | `review_item_diff` 对比驳回快照与当前申报；`check_evidence_duplicates` 看附件在全库的重复计数。 |
| AI 初审 | 审核页点「生成 AI 初审草稿」：先由规则匹配/确定性公式计算，信息不足或主观项再交给 DeepSeek；结果写入 `ai_review`，只作草稿，审核人可采纳或覆盖。 |
| 公示操作员 | 截止后调用 `publish_year(学年)`。所有已提交表单的条目终审通过/撤回、所有档案 A/B1 已录入、B1 不超过 80 分时，一次生成总分、A/B1/B2/C 分项、年级排名和校验码；草稿不参与。 |
| 全体角色 | 公示后用 `verify_publication(学年)` 重算摘要比对校验码，`intact=1` 表示未被篡改。 |
| 分析人员 | `published_results`、`class_result_distribution`、`project_submission_statistics`、`class_progress_stats`、`rule_version_chain`、`public_notice`。 |
| 管理员 | 维护 6 张主数据表；业务数据只读；`admin_stalled_forms` 监控卡公示；`abandon_form` 截止后作废；四张审计日志、`evidence_duplicates`、`publication_batch`、`status_change_log`。 |

## 完整性约束

- 单条申报分不超过项目单项上限；同表单同项目申报条数不超过 `max_items`。
- 终审核定分不低于 0、不超过申报分和单项上限；同表单同项目已通过条目合计加本次不超过 `total_cap`（若设置）。
- B1 换算后不超过 80 分；A 在 0-20 分；A/学业不合格标记直接决定最终不合格。
- 学年日期区间互不重叠；启用后不可修改起止日期与开放时刻；截止时间只许后延；已公示学年不能退回。
- 已使用规则及其项目不可修改（`require_unused_rule`）；规则版本链用 `parent_rule_id`，CHECK 禁止自环。
- 学生与审核人登录名互斥。
- 条目项目必须属于该学生本年度规则；必填材料缺失拒绝提交；驳回必须填写意见。
- 公示要求：已过截止时间、学年未公示、已提交表单无未终审条目、所有测评档案 A/B1 已录入且 B1 ≤ 80。
- 优秀人数按年级 `FLOOR(人数 × excellent_ratio)` 控制；A 不合格或学业不合格不参与优秀。

## AI 初审

- `scoring.py` 读取本地 `.env` 的 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`；`.env` 已在 `.gitignore` 中，不写入源码或文档。
- 规则能直接算的（论文、著作、课题、竞赛、知识产权）在 AI 识别出 `subtype/author_rank/author_count/team_size/award_level/award_rank` 后由本地函数复算；社会工作、志愿、实践活动等主观项采用 AI 建议分。
- AI 结果保存到 `ai_review`，只作审核参考；最终分数以 `review_record` 为准。终审采纳建议时状态记 `accepted`，覆盖时记 `overridden`。
- AI 不可用或返回异常时降级为“按申报分与单项上限截断”的规则草稿，不阻塞人工审核。
- API key 只在本地使用；由于它曾在对话中出现，建议在 DeepSeek 控制台轮换一次。

## 审计闭环

- 成功读取：`read_review_item`、`read_evidence`、`web_ai_context` 每次成功读取写入 `privacy_access_log`。
- 越权尝试：审核类过程在 SIGNAL 前把拒绝上下文写入会话变量，EXIT HANDLER 在 `ROLLBACK` 后补记 `access_denied_log`；对外报错消息不变。
- 管理操作：`abandon_form`、`publish_year` 过程内记录；6 张主数据表各有增/改/删 AFTER 触发器写入 `admin_operation_log`。
- 状态迁移：`status_change_log` 由学年/表单/条目三个 AFTER UPDATE 触发器写入，仅在状态实际变化时留痕。
- AI 审计：`ai_review` 记录来源、模型、提示版本、识别字段、建议分、置信度、理由、原始响应和最终采纳状态。

## 公示校验与查重

- 公示校验码：`publish_year` 在同一事务内对“学年|批次时刻|每个学生的(学号:总分:名次:A/B1/B2/C)”计算 SHA-256，写入 `publication_batch`；任何角色可 `verify_publication` 重算比对。
- 材料查重：按 `SHA2(file_body, 256)` 实时计算；`check_evidence_duplicates` 给审核人看本条目附件的全库活跃重复计数，只给计数；`evidence_duplicates` 供管理员按指纹分组。
- 规则版本链：`rule_version_chain` 递归视图沿 `parent_rule_id` 展开根版本、链深与路径。
- 状态变更日志：与 `admin_operation_log` 分工互补，记录业务实体生命周期。

## 运维

- 事件调度器：`open_due_years` 每分钟把到开放时刻的草稿学年置为 `open`；`review_due_years` 把过截止时刻的开放学年置为 `review`。`01` 以 `SET PERSIST` 开启，`demo.py` 另以 `--event-scheduler=ON` 兜底。
- 卡公示监控：`admin_stalled_forms` 列出截止后仍有未终审条目的已提交表单；管理员可延长窗口或 `abandon_form` 作废。
- 学年状态由数据库推进，应用层与人工只负责建学年与公示两个端点。

## 账号和权限

五个角色：`sa_student`、`sa_reviewer`、`sa_analyst`、`sa_publisher`、`sa_admin`。业务表 `login_name` 对应 MySQL 用户名；同一用户名只绑定一个人。初审必须绑定班级，辅导员及终审可限定班级或用空班级表示院系范围。

`demo.py` 自动创建演示账号（含管理员 `sa_demo_admin`）；管理员账号仅供 SQL 客户端与测试直连，不出现在网页演示账号列表。手工授权示例：

```sql
CREATE USER 'sa_demo_s001'@'localhost' IDENTIFIED BY '口令';
GRANT 'sa_student' TO 'sa_demo_s001'@'localhost';
SET DEFAULT ROLE 'sa_student' TO 'sa_demo_s001'@'localhost';
```

业务账号通过过程和视图访问；审核详情与材料由负责范围的审核账号读取；学生只能看本人材料元数据。管理员对 `evidence` 仅授权元数据列。分析视图省略姓名、学号和申报细节。

## 测试

安装依赖后，在项目目录运行：

```bat
python -m unittest discover -s tests -v
```

- `tests/test_workflow.py`：网页集成测试。核验基础分录入、B2 加分申报、上传下载与 SHA-256 校验、三级审核、公示、年级排名与重启持久（2026-2027 示例 106.40 分）。
- `tests/test_constraints.py`：约束负例与审计闭环。核验单项封顶/条数上限、学年时间锁与防重叠、24/25 规则匹配与 B1 公式、登录名互斥、学生自查、年级 20% 配额与三档等级、越权留痕、驳回重提 diff、截止作废、事件、管理员审计、公示校验码、材料查重、规则版本链与状态日志。
- `tests/test_scoring.py`：确定性规则单元测试（论文作者折算、竞赛团队均分、专利公式、著作、课题），不调用 DeepSeek。

三个套件各自新建并清理独立 MySQL 目录；测试需要本机装有 MySQL Server 8.4（非默认位置设置 `SA_MYSQL_BIN`）；可用 `SA_TEST_DIR` 指定临时目录父目录。
