# 学生素质综合测评系统

面向信息管理系的本科生综测系统。按 2024 级及以前、2025 级及以后两份实施细则计分：`S = A 基本素质（20）+ B1 学业成绩（80）+ B2 学术科研（加分）+ C 实践能力（加分）`；24 级 B1 = 平均绩点 × 20，25 级 B1 = 加权平均分 × 0.8；结果只有优秀/合格/不合格，优秀不超过年级 20%（不合格学生不占优秀名额），A 不合格或学业不合格直接不合格。

网页提供基础分录入、B2/C 加分申报、证明材料上传、三级审核、AI 初审草稿、结果公示和统计查询。后端通过 MySQL 账号和存储过程执行操作，数据库含 20 张业务表、4 张审计/日志表（共 24 张），满足 1NF、2NF 与 3NF（入学年、B2/C 组件等冗余传递依赖已消除）。

## 在 Windows 打开演示

1. 将项目解压到可写目录。电脑需要 Python 3.11 或更新版本，以及 MySQL Server 8.4。
2. 首次使用 AI 初审前，把 DeepSeek key 写入项目根目录的 `.env`（该文件已被 `.gitignore` 忽略）：
   ```
   DEEPSEEK_API_KEY=你的key
   DEEPSEEK_BASE_URL=https://api.deepseek.com
   DEEPSEEK_MODEL=deepseek-chat
   ```
   没有 key 时系统仍可运行，AI 草稿会降级为“按单项上限截断”的规则草稿。
3. 双击 **启动演示.cmd**。首次运行会安装 Python 依赖并初始化独立演示库，通常需要等待片刻。
4. 浏览器会打开 **http://127.0.0.1:8000**。在「体验演示账号」点击所需角色即可进入。按 **Ctrl+C** 停止服务。

演示只在本机监听，自动选择空闲端口启动独立 MySQL（事件调度器随实例开启）。数据保存在当前用户的 `%LOCALAPPDATA%\StudentAssessmentDemo`。想从头演示时，可将环境变量 `SA_DEMO_DIR` 指向新的空目录。MySQL 安装在非默认位置时，设置 `SA_MYSQL_BIN` 指向 MySQL 8.4 的 `bin` 目录。

## 演示路线

- **直接看结果**：以学生登录，在「测评结果」看 2025–2026 学年：S001 98.90 分、优秀、2024 级第 1 名；S006 92.77 分、优秀、2025 级第 1 名；S003/S008 分别因 A 不合格/学业不合格为不合格。统计分析员可看年级排名、班级分布和项目统计。
- **走完整流程**：选择 2026–2027 学年。先用班级初审账号进入「基础分录入」，给本班学生填 A 和 B1；再以学生身份建表、添加 B2/C 加分项、上传材料并提交；用「切换演示身份」依次走班级初审、辅导员复审、院系终审。终审可通过 AI 初审草稿参考给分，再人工采纳或覆盖。最后用公示管理员结束申报并发布。
- **AI 初审**：审核详情页点「生成 AI 初审草稿」。规则能直接算的（论文、著作、课题、竞赛、知识产权）会先由本地规则复算；不确定或主观项交给 DeepSeek；草稿只作参考，最终分数由审核人决定。
- **生成新结果**：终审完成后，结束申报并发布。切回学生账号即可看到本次测评结果。

演示账号和材料均为虚构。管理员账号 `sa_demo_admin` 由演示自动创建，仅供 SQL 客户端直连，不出现在网页演示账号列表。

## 接入已有 MySQL 库

已运行过建库脚本的用户，可以在 MySQL Workbench 中直接运行 `03_网页接口.sql` 一次。新库先运行 `01_创建数据库.sql`，需要虚构样例时运行 `02_演示数据.sql`，再运行 `03_网页接口.sql`。新学年、规则、人员和班级由管理员通过 SQL 配置。

业务人员使用各自的 MySQL 账号登录。先按 [数据库使用说明](使用说明.md) 绑定学生或审核人员并配置默认角色。公示和分析账号分别授予 `sa_publisher` 和 `sa_analyst`，管理员授予 `sa_admin`。示例：

```sql
GRANT 'sa_student' TO 'sa_demo_s001'@'localhost';
SET DEFAULT ROLE 'sa_student' TO 'sa_demo_s001'@'localhost';
```

在项目目录安装依赖后启动普通模式：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:SA_MYSQL_HOST = "127.0.0.1"
$env:SA_MYSQL_PORT = "3306"
.\.venv\Scripts\python.exe app.py
```

当前版本面向本机课程演示：网页应用进程在内存中保存登录会话，重启后需要重新登录。正式部署需配置 HTTPS 和数据库 TLS（`SA_HTTPS=1`、`SA_MYSQL_TLS_CA`），并使用适合部署的 WSGI 服务。

## 项目文件

| 文件 | 用途 |
| --- | --- |
| `01_创建数据库.sql` | 表结构、约束、真实口径评分、审核流程、审计、事件和权限 |
| `02_演示数据.sql` | 虚构的 24/25 级学生、A/B1 基础分、B2/C 加分、已公示学年和开放学年 |
| `03_网页接口.sql` | 网页所需的账号、草稿和学年接口 |
| `app.py`、`templates/`、`static/` | Flask 后端及响应式网页 |
| `scoring.py` | 规则匹配、确定性公式与 DeepSeek AI 初审草稿 |
| `demo.py`、`启动演示.cmd` | 独立演示库和启动入口 |
| `tests/test_workflow.py` | 基础分录入、B2/C 申报、三级审核、公示与重启的网页集成测试 |
| `tests/test_constraints.py` | 约束负例、年级配额、审计闭环测试 |
| `tests/test_scoring.py` | 确定性规则离线单元测试 |

安装依赖后，用 `python -m unittest discover -s tests -v` 运行测试（共 31 个用例）。测试会新建并清理独立的 MySQL 目录。

AI 初审调用 DeepSeek，key 仅从本地 `.env` 或环境变量读取；不要把 `.env` 提交到仓库。key 曾在对话中出现过，建议在 DeepSeek 控制台轮换一次。
